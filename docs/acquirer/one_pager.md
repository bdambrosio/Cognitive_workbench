# Tuuyi Claims Review

**Every claim a seller makes about their software, checked against the code, with a citation.**

Buyers of software companies rely on what the seller writes: the README, the technical overview, the sales deck. Tuuyi Claims Review reads those documents, extracts every factual assertion, and adjudicates each one against the seller's source. The result is a report the buyer's counsel and engineers can read side by side: a verdict per claim, and for each verdict the lines of code it rests on.

## How it works

1. **Enumerate.** Every assertion in the seller's documents becomes a claim, quoted verbatim, on a frozen surface reviewed by a person before the audit begins.
2. **Audit.** An agent adjudicates each claim against the code. Evidence is source only; documentation is never evidence. 100% of citations are verified mechanically before review.
3. **Review.** An independent reviewer, run as a separate process and optionally a different model, checks every finding against its own evidence. Nothing the auditor wrote about its own work reaches the reviewer.
4. **Report.** Findings are rated against the buyer's stated thresholds and delivered as a printable report with a covering letter.

## Why it holds up

- Over 95% of findings hold under independent review on our reference target.
- Every review exception is retested by a second reviewer.
- Claims of absence are settled by two complete searches of the tree, always.
- Every run pins the target commit, the harness commit, the model and its sampling settings. Runs are reproducible.
- Model-agnostic: runs on hosted or on-premises models.
- The seller's dataroom is never visible to the buyer.

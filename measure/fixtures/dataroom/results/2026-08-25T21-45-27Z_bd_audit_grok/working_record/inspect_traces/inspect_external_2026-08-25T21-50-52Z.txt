12|## 1. Purpose
13|
14|Body is the onboard software stack for a differential-drive robot chassis. It provides sensor acquisition, motor control, and safety supervision as a set of independent communicating processes linked by Zenoh. The desktop agent (Jill, running on the CW workstation) connects to the same Zenoh network and interacts with Body exclusively through published topics. Body has no knowledge of Jill's internals; Jill has no knowledge of Body's process structure. The Zenoh topic schema defined in this document is the contract between them.
15|
16|## 2. Hardware Inventory
17|

19||---|---|---|
20|| Cytron MDD10A dual 10A motor driver | GPIO: 2x PWM + 2x DIR | Channel A = left motor, Channel B = right motor |
21|| Pololu #4752 30:1 gearmotor w/ encoder (x2) | GPIO: 2x quadrature (A/B per motor) | 64 CPR motor shaft, 1920 CPR output shaft. 330 RPM no-load @ 12V. Stall: 14 kg·cm / 5.5A |
22|| LDROBOT STL-19P lidar | USB serial | 360° 2D scan, ~10Hz typical |
23|| OAK-D-Lite | USB3 (DepthAI) | Stereo depth, RGB, onboard IMU (BNO086) |
24|| Raspberry Pi 5 | — | 4-core, 8GB assumed. Runs all Body processes |

70|### 3.1 Process Inventory
71|
72|| Process | Owns | Publishes | Subscribes |
73||---|---|---|---|
74|| `motor_controller` | MDD10A GPIO, encoder GPIO | `body/odom`, `body/motor_state` | `body/cmd_vel`, `body/cmd_direct` |
75|| `lidar_driver` | STL-19P USB | `body/lidar/scan` | — |
76|| `oakd_driver` | OAK-D-Lite USB | `body/oakd/depth`, `body/oakd/imu`, `body/oakd/rgb` (optional) | `body/oakd/config` (optional) |
77|| `watchdog` | safety authority | `body/status` | `body/heartbeat`, all `body/*` for monitoring |
78|| `launcher` | process lifecycle | — | — |
79|
80|### 3.2 Design Principles
81|
82|- Each process is a standalone Python script with its own `main()` and Zenoh session.
83|- No shared memory, no threading across process boundaries.
84|- Processes do not import each other. The Zenoh topic schema is the only coupling.
85|- Every process logs to stdout. The launcher captures and tags output.
86|- Every process handles SIGTERM gracefully: releases hardware, closes Zenoh session, exits.
87|- Motor output defaults to zero (stopped) on startup and on any error.
88|
89|## 4. Zenoh Configuration
90|
91|### 4.1 Transport
92|
93|Body processes use Zenoh in **peer mode** for local communication. The desktop agent connects via Zenoh **router mode** or direct peer over TCP.
94|
95|Recommended: run a `zenohd` router on the Pi that both local processes and the remote desktop connect to. This simplifies discovery and avoids multicast issues over wifi.
96|
97|```
98|# /etc/zenoh/config.json (Pi router)
99|{
100|  "mode": "router",
101|  "listen": {
102|    "endpoints": ["tcp/0.0.0.0:7447"]
103|  }
104|}
105|```
106|
107|Each Body process connects as a peer to `tcp/localhost:7447`. The desktop agent connects to `tcp://<pi-ip>:7447`.
108|
109|### 4.2 Key Expression Namespace
110|
111|All Body topics live under the `body/` prefix.
112|
113|```
114|body/
115|  cmd_vel            # commanded twist velocity (from Jill)
116|  cmd_direct         # direct wheel velocities (from Jill, low-level override)
117|  heartbeat          # periodic heartbeat from Jill
118|  odom               # encoder-derived odometry
119|  motor_state        # motor driver status
120|  lidar/
121|    scan             # 2D laser scan
122|  oakd/
123|    depth            # depth frame or point cloud
124|    imu              # IMU readings
125|    rgb              # color frame (optional, high bandwidth)
126|    config           # runtime pipeline reconfiguration (optional)
127|  status             # system-level health from watchdog
128|  emergency_stop     # published by watchdog on safety violation
129|```

131|## 5. Message Schemas
132|
133|All messages are JSON-encoded UTF-8 strings published as Zenoh values. Timestamps are Unix epoch float (seconds with microsecond precision). All spatial units are SI: meters, radians, meters/second, radians/second.
134|
135|### 5.1 `body/cmd_vel` (Jill → motor_controller)
136|
137|Twist command in robot body frame. Linear is forward/back, angular is rotation (positive = counterclockwise viewed from above).
138|
139|```json
140|{
141|  "ts": 1713264000.123456,
142|  "linear": 0.2,
143|  "angular": 0.0,
144|  "timeout_ms": 500
145|}
146|```
147|
148|- `linear`: m/s, positive = forward. Clamped by motor_controller to hardware limits.
149|- `angular`: rad/s, positive = CCW.
150|- `timeout_ms`: if no new `cmd_vel` arrives within this window, motor_controller sets output to zero. Safety backstop independent of watchdog.
151|
152|### 5.2 `body/cmd_direct` (Jill → motor_controller)
153|
154|Direct wheel velocity command. Bypasses twist-to-differential math. For calibration and testing.
155|
156|```json
157|{
158|  "ts": 1713264000.123456,
159|  "left": 0.15,
160|  "right": 0.15,
161|  "timeout_ms": 500
162|}
163|```
164|
165|- `left`, `right`: m/s at wheel surface. Sign convention: positive = forward.
166|
167|### 5.3 `body/odom` (motor_controller → Jill)
168|
169|Dead-reckoned pose from encoder integration. Frame: robot starting position at origin, x-forward, y-left, theta CCW from x.
170|
171|```json
172|{
173|  "ts": 1713264000.123456,
174|  "x": 0.0,
175|  "y": 0.0,
176|  "theta": 0.0,
177|  "vx": 0.0,
178|  "vtheta": 0.0,
179|  "left_ticks": 0,
180|  "right_ticks": 0,
181|  "dt_ms": 20
182|}
183|```
184|
185|- `x`, `y`: meters from origin.
186|- `theta`: radians, normalized to [-π, π].
187|- `vx`, `vtheta`: instantaneous velocity estimates.
188|- `left_ticks`, `right_ticks`: raw cumulative encoder counts. Allows Jill to do her own integration if desired.
189|- `dt_ms`: time since last odom publication.
190|
191|### 5.4 `body/motor_state` (motor_controller → all)
192|
193|```json
194|{
195|  "ts": 1713264000.123456,
196|  "left_pwm": 0.0,
197|  "right_pwm": 0.0,
198|  "left_dir": "fwd",
199|  "right_dir": "fwd",
200|  "e_stop_active": false,
201|  "cmd_timeout_active": false
202|}
203|```
204|
205|- PWM values are duty cycle 0.0–1.0.
206|- `e_stop_active`: true if watchdog has triggered emergency stop.
207|- `cmd_timeout_active`: true if no `cmd_vel`/`cmd_direct` received within timeout window.
208|
209|### 5.5 `body/lidar/scan` (lidar_driver → Jill)
210|
211|```json
212|{
213|  "ts": 1713264000.123456,
214|  "angle_min": 0.0,
215|  "angle_max": 6.2832,
216|  "angle_increment": 0.01745,
217|  "range_min": 0.05,
218|  "range_max": 12.0,
219|  "ranges": [1.2, 1.3, 1.1, "..."],
220|  "intensities": [200, 195, 210, "..."],
221|  "scan_time_ms": 100
222|}
223|```
224|
225|- Angles in radians. 0 = forward, increasing CCW.
226|- Invalid/out-of-range readings: `null` in the array.
227|- `intensities`: included if the STL-19P provides them, omit field otherwise.
228|
229|### 5.6 `body/oakd/imu` (oakd_driver → Jill)
230|
231|```json
232|{
233|  "ts": 1713264000.123456,
234|  "accel": {"x": 0.0, "y": 0.0, "z": 9.81},
235|  "gyro": {"x": 0.0, "y": 0.0, "z": 0.0},
236|  "mag": {"x": 0.0, "y": 0.0, "z": 0.0},
237|  "orientation": {"w": 1.0, "x": 0.0, "y": 0.0, "z": 0.0}
238|}
239|```
240|
241|- `accel`: m/s², sensor frame.
242|- `gyro`: rad/s.
243|- `mag`: if available from BNO086, omit if not configured.
244|- `orientation`: quaternion from BNO086 onboard fusion, if available.

12|## 1. Purpose
13|
14|Body is the onboard software stack for a differential-drive robot chassis. It provides sensor acquisition, motor control, and safety supervision as a set of independent communicating processes linked by Zenoh. The desktop agent (Jill, running on the CW workstation) connects to the same Zenoh network and interacts with Body exclusively through published topics. Body has no knowledge of Jill's internals; Jill has no knowledge of Body's process structure. The Zenoh topic schema defined in this document is the contract between them.

80|### 3.2 Design Principles
81|
82|- Each process is a standalone Python script with its own `main()` and Zenoh session.
83|- No shared memory, no threading across process boundaries.
84|- Processes do not import each other. The Zenoh topic schema is the only coupling.
85|- Every process logs to stdout. The launcher captures and tags output.
86|- Every process handles SIGTERM gracefully: releases hardware, closes Zenoh session, exits.
87|- Motor output defaults to zero (stopped) on startup and on any error.

131|## 5. Message Schemas
132|
133|All messages are JSON-encoded UTF-8 strings published as Zenoh values. Timestamps are Unix epoch float (seconds with microsecond precision). All spatial units are SI: meters, radians, meters/second, radians/second.
134|
135|### 5.1 `body/cmd_vel` (Jill → motor_controller)
136|
137|Twist command in robot body frame. Linear is forward/back, angular is rotation (positive = counterclockwise viewed from above).
138|
139|
140|{
141|  "ts": 1713264000.123456,
142|  "linear": 0.2,
143|  "angular": 0.0,
144|  "timeout_ms": 500
145|}
146|
147|
148|- `linear`: m/s, positive = forward. Clamped by motor_controller to hardware limits.
149|- `angular`: rad/s, positive = CCW.
150|- `timeout_ms`: if no new `cmd_vel` arrives within this window, motor_controller sets output to zero. Safety backstop independent of watchdog.
151|
152|### 5.2 `body/cmd_direct` (Jill → motor_controller)
153|
154|Direct wheel velocity command. Bypasses twist-to-differential math. For calibration and testing.
155|
156|
157|{
158|  "ts": 1713264000.123456,
159|  "left": 0.15,
160|  "right": 0.15,
161|  "timeout_ms": 500
162|}
163|
164|
165|- `left`, `right`: m/s at wheel surface. Sign convention: positive = forward.
166|
167|### 5.3 `body/odom` (motor_controller → Jill)
168|
169|Dead-reckoned pose from encoder integration. Frame: robot starting position at origin, x-forward, y-left, theta CCW from x.
170|
171|
172|{
173|  "ts": 1713264000.123456,
174|  "x": 0.0,
175|  "y": 0.0,
176|  "theta": 0.0,
177|  "vx": 0.0,
178|  "vtheta": 0.0,
179|  "left_ticks": 0,
180|  "right_ticks": 0,
181|  "dt_ms": 20
182|}
183|
184|
185|- `x`, `y`: meters from origin.
186|- `theta`: radians, normalized to [-π, π].
187|- `vx`, `vtheta`: instantaneous velocity estimates.
188|- `left_ticks`, `right_ticks`: raw cumulative encoder counts. Allows Jill to do her own integration if desired.
189|- `dt_ms`: time since last odom publication.

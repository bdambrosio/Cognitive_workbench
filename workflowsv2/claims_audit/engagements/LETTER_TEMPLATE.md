# Engagement letter

**DRAFT PLACEHOLDER. The practice replaces this file with the letter its attorney settles. An engagement shows its own `letter.md` when one exists in its directory, else this template.**

Tuuyi will carry out a claims review for the client named at intake.

**What the review is.** The claims in the documents the client names are listed and frozen, then each is tested against the repository and materials supplied. Every finding cites the file and lines it rests on. A second, independent pass re-reads every finding's evidence. Findings are rated against the thresholds the client states at intake. A person at the practice reads the result before it is released, and who released it is recorded with the report. A signed opinion is a separate service, attested due diligence.

**How we read a claim.** We read each assertion in the documents you name the way a reasonable buyer would read it in the context of this transaction: in its ordinary sense, as one statement, with the seller's own documentation as the specification of what the software is said to do. We test it against the code, configuration and build files that determine what the software does. Documentation restates a claim and does not settle it, except where the claim is about the document itself. Vague general statements that a reasonable buyer would not rely on are not treated as claims. Where the ordinary sense of a claim implies properties the seller did not state, we report those separately, marked as implied. The report states findings on each claim; it expresses no opinion on the software, the seller or the transaction.

**Claims about behaviour.** Where a claim says what the software does when it runs, how fast, how much memory, what a model answers, what happens under load, we verify the mechanism the code provides for it: that the feature is present, wired and configured. Whether the software behaves that way in operation is not settled by reading code. Such claims are reported as unsettled unless the seller supplies records of the behaviour, and each produces a question to the seller. This applies with particular force to features driven by a language model, whose conduct is not fixed by the code that calls it.

**What it is not.** Not a penetration test, not a review of code quality or architecture, not legal or financial advice, and not a judgement on claims the materials cannot settle, which are reported as unsettled.

**Materials.** The seller supplies the repository and the documents to be examined on a page of this site that only the seller and the practice can open, arranges them there, and says when they are complete. Where the client holds the materials, the client supplies them the same way. The client names the documents that carry the seller's claims. The client does not receive the materials: the report names files by their path and quotes the lines each finding rests on, and nothing more of them leaves the engagement. The practice holds the materials on hardware it controls, in an environment created for this engagement and deleted afterwards. The model that reads them is a cloud model service that retains no data.

**Turnaround.** The target is the report within 24 to 48 hours, on working days, of the seller marking the materials complete, for most repositories. It is a target, not a guarantee.

**Retention.** The engagement file, the record and the report are kept for the period stated at intake and then deleted.

**Fee.** Pilot engagements are free. A later engagement is $499 for most repositories, paid by the seller; a larger target is quoted after intake, and the fee is agreed before work begins.

**Limitation of liability.** To be settled by the practice's attorney.

By accepting this letter on the engagement page, the client agrees to these terms.
